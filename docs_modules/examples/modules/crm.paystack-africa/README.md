# Модуль «Paystack African Payments Gateway» для TropaTT CRM

## Назначение и текущий охват
Модуль подключается к Paystack на уровне рабочего пространства, создаёт hosted checkout-ссылки и проверяет их состояние через официальный Transaction API. Текущая версия хранит транзакции и контактный email в CRM, но пока не связывает платежи с карточками контрагентов, счетами или коммерческими предложениями. Поддерживаются валюты NGN, GHS, ZAR, KES и USD; доступность конкретной валюты и метода оплаты определяется аккаунтом Paystack.

## Архитектура и безопасность
1. **Данные карты**:
   - CRM не принимает и не хранит данные карт. Инициализация выполняется через Paystack API, а покупателю возвращается только проверенный HTTPS URL Paystack Checkout. Это само по себе не является подтверждением соответствия PCI DSS.
2. **Сверка**:
   - Статус оплаты считается успешным только после ответа Verify API с совпадающими reference, суммой и валютой. Наличие ссылки Checkout не подтверждает оплату.
   - Reference резервируется в БД до запроса и уникален в рабочем пространстве. Если ответ Paystack потерян или не прошёл проверку, запись получает статус `initialization_unknown`; повторное создание с тем же reference блокируется. Сначала выполните проверку этой reference, прежде чем создавать новую платёжную ссылку.
3. **Webhook**:
   - Для каждого рабочего пространства создаётся отдельный URL с непредсказуемым 128-битным идентификатором. Подпись `X-Paystack-Signature` сверяется как HMAC-SHA512 по исходным байтам тела и секретному ключу. Повторные события идемпотентны; неизвестная транзакция отклоняется, а несовпадение суммы или валюты отправляет запись на ручную проверку.
4. **Аудит**:
   - Записываются переходы состояния и минимальные признаки сверки; ключи и полный ответ провайдера не сохраняются.

## Настройка ключа
На странице модуля выберите тестовую или рабочую среду и сохраните соответствующие public/secret keys. Secret key шифруется AES-256-GCM с ключом приложения `APP_KEY` (64 hex символа); он не возвращается в браузер, а поле очищается после сохранения. Затем используйте «Проверить подключение». Для реального приёма webhook скопируйте URL из настроек модуля в Paystack Dashboard. Не передавайте секрет через URL, MCP-аргументы или клиентский JavaScript. Live-режим может принимать реальные платежи.

Входящий webhook ограничен 256 КиБ до декодирования тела. Для интеграции требуется исходящее HTTPS-соединение PHP с `api.paystack.co`; на shared-хостинге должны быть доступны PHP OpenSSL и корректная TLS-проверка. Если `APP_KEY` не настроен, ключи не сохраняются и операции закрываются безопасно.
