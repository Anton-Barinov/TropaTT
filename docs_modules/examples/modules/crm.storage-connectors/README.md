# Модуль «Внешние хранилища» (crm.storage-connectors)

Модуль позволяет сохранить настройки S3-совместимого или Nextcloud/WebDAV-хранилища, проверить соединение и вручную переносить туда существующие файлы выбранного рабочего пространства.

**Важно:** текущая версия не подключена к штатному пути загрузки, скачивания и предпросмотра файлов CRM. Новые файлы продолжают храниться штатно; внешний backend пока не является основным файловым хранилищем и автоматического локального fallback нет. Не включайте модуль как средство резервного копирования или гарантированного хранения файлов.

## Поддерживаемые провайдеры
1. **S3-Compatible Storage**:
   - Реализация стандарта AWS SigV4 на нативном PHP (cURL / hash_hmac).
   - Поддержка произвольных S3 endpoints: MinIO, Selectel, Timeweb Cloud S3, Cloudflare R2, AWS S3.
   - Поддержка создания временных подписанных ссылок (Pre-signed GET URLs, до 300 секунд).
2. **Nextcloud / WebDAV**:
   - Методы `PROPFIND`, `PUT`, `GET`, `DELETE` поверх HTTPS.
   - Поддержка передачи контрольных сумм в заголовках `OC-Checksum: SHA256:...`.

## Безопасность и архитектура
- **Проверки доступа к настройкам и переносу**: модульные API требуют соответствующих `settings.view`/`settings.edit` и активного рабочего пространства. Он не меняет RBAC штатной выдачи файлов и пока не обслуживает скачивание или предпросмотр из внешнего хранилища.
- **Шифрование ключей**: секреты шифруются AES-256-GCM с ключом, производным от `APP_KEY`; если `APP_KEY` или OpenSSL недоступны, модуль отказывает в сохранении и подключении.
- **Защита исходящих запросов**: только HTTPS на порту 443, блокировка localhost/private/reserved IP, DNS pinning в cURL, без переходов по redirect.
- **Защита файлов**: предел размера 20 MB, проверка локального пути и symlink до чтения, повторная проверка inode/размера/времени изменения после чтения, запрет `.`/`..` в путях объектов.
- **Изоляция по workspace (Multi-Tenancy)**: настройки каждого клиента/организации хранятся в `crm_storage_configs` с изоляцией по `organization_id`.
- **Перенос существующих файлов**: `migrate-batch` копирует до 15 файлов за вызов; локальные оригиналы не удаляются. Файлы с ошибками исключаются из очереди, поэтому один постоянно падающий файл не блокирует остальные. На странице видны код причины и число попыток; оператор может повторить конкретный файл после устранения причины. Успешный повтор снимает ошибку. Другие workspace не могут увидеть или повторить файл. Удалённый ключ включает workspace, ID файла и SHA-256 содержимого: параллельный перенос двух разных снимков не перезаписывает объект, на который уже ссылается выигравшая DB-связь. Потерявший гонку объект остаётся безопасным orphan; автоматическое удаление не выполняется без подтверждённого контракта листинга и безопасной очистки у провайдера. Повтор того же содержимого идемпотентен.

## REST API
- `GET /api/v1/_module/crm.storage-connectors/preflight` — проверка окружения хостинга.
- `GET /api/v1/_module/crm.storage-connectors/config` — получение настроек без возврата секретов.
- `POST /api/v1/_module/crm.storage-connectors/config` — сохранение реквизитов в зашифрованном виде.
- `POST /api/v1/_module/crm.storage-connectors/test-connection` — тест соединения с провайдером.
- `POST /api/v1/_module/crm.storage-connectors/migrate-batch` — ручной перенос следующей партии файлов.
- `GET /api/v1/_module/crm.storage-connectors/migration-failures` — список ошибок переноса только для активного workspace.
- `POST /api/v1/_module/crm.storage-connectors/migration-retry` — повторный перенос одного файла с проверкой workspace и полномочий на чтение.

## MCP Инструменты
- `storage_preflight_check`
- `storage_config_status`
- `storage_test_connection`

Эти MCP-инструменты проверяют окружение, состояние настроек и соединение. Они не загружают, не скачивают и не синхронизируют файлы CRM.
