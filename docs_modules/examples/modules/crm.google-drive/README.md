# Google Drive — модуль TropaTT CRM

Модуль подключает один Google Drive OAuth-клиент к текущему рабочему пространству, проверяет учётную запись и вручную передаёт в её Drive отдельный файл CRM. Передача ограничена файлами до 20 МБ, доступными текущему пользователю; карантинные и удалённые файлы отклоняются. Новые файлы остаются приватными, публичные разрешения не создаются. Модуль не меняет штатное хранилище CRM, не синхронизирует каталог автоматически и не скачивает удалённые файлы обратно.

## Подготовка Google OAuth

1. В Google Cloud Console создайте проект и включите Google Drive API.
2. Настройте OAuth consent screen и создайте OAuth client типа Web application.
3. Для получения refresh token используйте доверенный OAuth-инструмент/flow владельца проекта с `access_type=offline`, `prompt=consent` и минимальным scope `https://www.googleapis.com/auth/drive.file`. Не отправляйте refresh token в чат, логи CRM, тикеты или Git.
4. В CRM откройте модуль в том рабочем пространстве, куда должны передаваться файлы. Введите client ID, client secret, refresh token. При желании укажите ID существующей целевой папки Drive; если поле пустое, файл будет создан в корне владельца OAuth-токена.
5. Нажмите «Сохранить настройки», затем «Проверить подключение». Только после успешной проверки используйте ручную передачу файла по его CRM public ID.

Токены сохраняются с AES-256-GCM и производным от `APP_KEY` ключом. На хостинге без корректно заданного `APP_KEY` модуль откажется сохранять секреты. Смена OAuth-клиента аннулирует кэш access token и сбрасывает подтверждённый адрес аккаунта.

## Безопасность и границы

- Версия 1.0.7 добавляет прямую миграцию уже установленных схем: новые строки больше не наследуют workspace `1` и включённое по умолчанию состояние. Существующие workspace ID и пользовательские настройки сохраняются.
- Каждый credential и file mapping привязан к `workspace_id`; MCP и HTTP перед передачей подтверждают актёра, его workspace, доступ к исходному файлу и результат `canDownloadInternal`.
- OAuth refresh token и access token шифруются в БД; API статуса возвращает только факт настройки и подтверждённый email. Секреты нигде не возвращаются.
- Запросы выполняются только к фиксированным HTTPS Google OAuth/Drive API hosts, порт 443, TLS certificate/hostname verification, DNS/IP safety validation с pinning и без redirects.
- Локальный файл проверяется до чтения: запись, symlink, quarantine, размер и совпадение метаданных; максимум 20 МБ. HTTP/API ответ ограничен 256 KiB.
- Идентификатор в Google Drive записывается только после ответа API с подтверждёнными id, именем, размером и appProperties с workspace/file ID/SHA-256. Повторная отправка того же содержимого идемпотентна; изменённое содержимое обновляет ранее связанный файл, если его ownership markers совпадают.
- Публичные разрешения не запрашиваются. `webViewLink` доступен только пользователям, которым Google Drive уже разрешает открывать файл.
- Загрузка файла производится в память; лимит 20 МБ ограничивает буфер. На очень низком PHP memory_limit следует использовать меньшие файлы.

## API

- `GET /api/v1/_module/crm.google-drive/status` — состояние настройки рабочего пространства без секретов.
- `POST /api/v1/_module/crm.google-drive/settings` — сохранение OAuth-настроек.
- `POST /api/v1/_module/crm.google-drive/test-connection` — refresh OAuth token и проверка `drive/v3/about`.
- `POST /api/v1/_module/crm.google-drive/upload-file` — передача доступного файла CRM в Google Drive.

## Ограничения

Нужны исходящие HTTPS-запросы к Google, cURL, OpenSSL и постоянный `APP_KEY`. Автоматические folder/project sync, Drive-to-CRM download, права доступа, удаление remote objects и фоновые большие/резюмируемые передачи не реализованы. До получения OAuth credentials провайдерный happy path и фактическую выдачу scope нельзя подтвердить; негативные проверки и локальные проверки модуля остаются доступными.
