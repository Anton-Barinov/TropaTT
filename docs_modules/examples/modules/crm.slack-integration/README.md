# Модуль crm.slack-integration — Уведомления в Slack

Отправка уведомлений TropaTT в каналы Slack через [Incoming Webhooks](https://api.slack.com/messaging/webhooks).

## Возможности

- Подключения (Slack Incoming Webhook URL, хранится зашифрованным — aes-256-gcm на `APP_SECRET`).
- Тестовая отправка сообщения.
- Очередь доставки с cron-обработчиком и retry (подходит для shared-хостинга, где нельзя держать долгие запросы).
- Правила-шаблоны сообщений (событие → подключение + шаблон с плейсхолдерами).
- **Автоматическая подписка на события ядра** через систему модульных хуков — без правок ядра и без ручной настройки workflow.
- Endpoint `POST /_module/crm.slack-integration/notify` для вызова из workflow (`call_webhook`) и внешних webhook; передавайте `organization_public_id` соответствующего workspace.

## Рабочие пространства (v1.1.1)

- Подключения Slack, правила и очередь доставок изолированы по выбранному workspace; API без активного контекста возвращает пустой результат/ошибку и не раскрывает чужие объекты по ID.
- Событийный обработчик принимает только контекст с `organization_id`, выбирает правила и обогащает подписи сущностей только в этом workspace. Фоновый отправитель восстанавливает workspace каждой доставки и получает webhook URL только из подключения этого workspace.
- Для `POST /notify` требуется `organization_public_id`; правило и подключение должны относиться к указанному workspace.
- Старые записи назначаются workspace только когда создатель подключения состоит ровно в одном workspace. Неоднозначные записи остаются закрытыми для API/очереди; создайте подключение заново в правильном workspace.

## Автоматические уведомления по событиям

Модуль подписывается на жизненный цикл ядра и при наступлении события автоматически ставит уведомление в очередь доставки для каждого включённого правила с подходящим `event_code`:

| Событие | Описание |
|---|---|
| `task.created` | задача создана |
| `task.updated` | задача изменена |
| `task.status_changed` | сменён статус задачи |
| `task.assignee_changed` | сменён исполнитель задачи |
| `task.deleted` | задача удалена |
| `comment.added` | добавлен комментарий |
| `file.uploaded` | загружен файл |
| `project.created` / `project.updated` / `project.deleted` | жизненный цикл проекта |
| `user.created` / `user.updated` / `user.deleted` | жизненный цикл пользователя |

Для обратной совместимости поддерживаются и старые коды с подчёркиванием (`task_created`, `task_status_changed`, `comment_added` и т.д.) — они автоматически мапятся на новые точечные имена.

### Как настроить

1. Создайте Incoming Webhook в Slack и добавьте подключение в модуле.
2. Создайте правило: выберите подключение, событие и шаблон текста.
3. Готово — при наступлении события уведомление попадёт в очередь и будет отправлено cron-обработчиком.

## Плейсхолдеры шаблона

`{event}`, `{task}` / `{task_title}`, `{task_id}`, `{project}` / `{project_title}`, `{status}`, `{old_status}`, `{user}` / `{actor}`, `{assignee}`, `{comment}`, `{file}`.

Имена, заголовки и текст комментария/файла подтягиваются модулем автоматически из БД (payload событий ядра содержит только id), поэтому шаблоны остаются читаемыми.

## Безопасность

- Webhook URL — секрет: шифруется, не возвращается в API и не пишется в логи.
- Разрешены только хосты `hooks.slack.com` (конфигурируется через `allowed_webhook_hosts`).
- Все подключения и записи очереди привязаны к `organization_id`. Объектные запросы фильтруются по текущему workspace; `created_by_user_id` остаётся дополнительным правилом прав, а не заменой tenant scope.

## Права

- `module.slack-integration.view` — просмотр подключений и доставок.
- `module.slack-integration.manage` — управление подключениями и правилами.
- `module.slack-integration.secret_manage` — запись/чтение секретов (создание/изменение подключений).
