# Установка CRM — Полное руководство

В этом руководстве описан процесс установки CRM через новый 9-шаговый мастер установки (`install/index.php`).

---

## Системные требования

### Минимальные

| Компонент | Требование |
|-----------|-----------|
| **PHP** | 8.1 или новее |
| **База данных** | MySQL 5.7+ / MariaDB 10.3+ |
| **Веб-сервер** | Apache, Nginx, PHP built-in server |
| **PHP расширения** | `pdo`, `pdo_mysql`, `mbstring`, `json`, `fileinfo`, `openssl`, `ctype`, `curl` |
| **Права на запись** | `api/` (для `.env`), `storage_api/` (для сессий, кэша, логов) |

### Рекомендуемые

| Компонент | Рекомендация |
|-----------|-------------|
| **PHP** | 8.2+ |
| **MySQL** | 8.0+ |
| **Память** | `memory_limit ≥ 128M` |
| **Время выполнения** | `max_execution_time ≥ 60s` |

### Поддерживаемые хостинги

CRM работает на любом shared-хостинге без необходимости прав root/sudo:

- ✅ **cPanel** / **Plesk** / **ISPmanager** — стандартная установка
- ✅ **XAMPP** / **MAMP** / **Laragon** — локальная разработка
- ✅ **PHP built-in server** — `php -S localhost:8080 -t .`
- ✅ **Любой shared-хостинг** с PHP 8.1+ и MySQL

Не требуется: Docker, systemd, Redis, Memcached, Node.js, права root.

## Быстрый старт (5 минут)

### 1. Загрузите файлы

Скопируйте ВСЕ файлы CRM в корневую директорию сайта (обычно `public_html/` или `htdocs/`):

```
your-site.com/
├── api/
├── web/
├── install/        ← Новый мастер установки
├── modules/
├── storage_api/
└── index.php
```

### 2. Откройте установщик

Перейдите в браузере:

```
https://your-site.com/install/index.php
```

### 3. Пройдите 9 шагов мастера

Мастер проведёт вас через все этапы настройки. Каждый шаг описан ниже.

### 4. Удалите папку install/

После успешной установки **обязательно удалите** директорию `install/`:

```bash
rm -rf install/
```

Это критически важно для безопасности сервера!

## Пошаговое руководство

### Шаг 1 — Приветствие и проверка системы

Мастер автоматически проверяет:

- Версию PHP (требуется 8.1+)
- Наличие обязательных PHP-расширений
- Права на запись в директории `api/` и `storage_api/`
- Доступность драйвера MySQL

Каждая проверка отображается с иконкой:
- ✅ — проверка пройдена
- ⚠️ — предупреждение (не блокирует установку)
- ❌ — критическая ошибка (кнопка «Далее» заблокирована)

**Если проверка не пройдена:** следуйте инструкциям на экране. Обычно требуется установить PHP-расширение или выставить права на запись (`chmod 755` или `chmod 777`).

---

### Шаг 2 — База данных

Выберите тип базы данных:

**MySQL / MariaDB** (рекомендуется):
- **Хост** — обычно `localhost` или `127.0.0.1`
- **Порт** — `3306` (стандартный)
- **База данных** — имя БД (должна существовать)
- **Пользователь** — пользователь MySQL с правами на создание таблиц
- **Пароль** — пароль пользователя БД
- **Префикс таблиц** — `crm_` (по умолчанию)

Нажмите **«Проверить подключение»** чтобы убедиться, что параметры верны. Мастер попытается подключиться к БД и покажет результат.

**SQLite** (упрощённый режим):
- База данных будет создана автоматически в `storage_api/database.sqlite`
- Не требует настройки подключения

> **Примечание:** SQLite подходит для тестирования и небольших инсталляций. Для production рекомендуется MySQL.

### Шаг 4 — Роли и права доступа

**Ключевой шаг** настройки безопасности системы.

Для каждой роли можно:
1. **Раскрыть карточку роли** — нажать на название роли
2. **Настроить права** — отметить нужные разрешения по 8 категориям:
   - 👥 Клиенты и контакты
   - 📋 Задачи и проекты
   - 👤 Команда и пользователи
   - 📚 База знаний
   - 📥 Заявки (Intake)
   - 🤖 AI-функции
   - 🔧 Инструменты (экспорт, импорт, API, вебхуки)
   - ⚙️ Администрирование (настройки, роли, логи)

3. **«Выбрать все» / «Снять все»** — быстрая настройка категории

Если нужна роль, которой нет в отраслевом шаблоне, используйте кнопку **«+ Добавить свою роль»** внизу страницы:
- Введите название роли
- Заполните slug (или он сгенерируется автоматически)
- Настройте права как для обычной роли

**Роль «Администратор» всегда имеет все права** и пометку «системная» (нельзя удалить).

### Шаг 5 — Администратор системы

Создайте главного администратора CRM:

- **Полное имя** — как будет отображаться в системе
- **Email** — будет использоваться для входа и уведомлений
- **Логин** — для входа в систему
- **Пароль** — минимум 8 символов (индикатор надёжности покажет уровень)
- **Подтверждение пароля** — повторите пароль

Администратор получит:
- Полный доступ ко всем функциям (`is_root = 1`)
- Роль «Администратор» со всеми правами
- Возможность создавать других пользователей и назначать роли

### Шаг 6 — Дополнительные пользователи (опционально)

Можно сразу создать аккаунты для команды:

- Нажмите **«+ Добавить пользователя»**
- Заполните: имя, email, пароль, роль (из настроенных на шаге 4)
- Повторите для каждого сотрудника

Каждый пользователь получит:
- Собственный логин (email) и пароль
- Назначенную роль с соответствующими правами

Этот шаг можно **пропустить** — пользователей можно добавить позже через админ-панель.

### Шаг 7 — Демо-данные (опционально)

Включите опцию **«Установить демо-данные»** чтобы получить:

- 2-3 тестовых контрагента в зависимости от выбранной отрасли
- Примеры для ознакомления с интерфейсом

Демо-данные можно безопасно удалить после знакомства с системой.

### Шаг 8 — Настройка почты

**PHP mail()** (по умолчанию):
- Использует встроенную функцию PHP
- Не требует настройки
- Работает на большинстве хостингов

**SMTP** (рекомендуется для надёжной доставки):
- **SMTP хост** — например, `smtp.gmail.com`
- **Порт** — `587` (TLS) или `465` (SSL)
- **Шифрование** — TLS или SSL
- **Логин** — email или API-ключ
- **Пароль** — пароль или app-specific password

Нажмите **«Отправить тестовое письмо»** для проверки:
- В режиме SMTP — проверяется подключение к серверу и приветствие
- В режиме mail() — отправляется реальное письмо на email администратора

Этот шаг можно **пропустить** — почту можно настроить позже в админ-панели.

## После установки

### 1. Удалите установщик

```bash
rm -rf install/
```

Либо через FTP/файловый менеджер хостинга удалите папку `install/`.

### 2. Войдите в систему

Перейдите на `https://your-site.com/web/index.php?route=login` и войдите с учётными данными администратора.

### 3. Настройте cron (рекомендуется)

Для работы фоновых задач (AI, уведомления, recurring-правила) настройте cron:

```bash
* * * * * php /path/to/site/web/cron.php
```

Или используйте внешний сервис: [cron-job.org](https://cron-job.org) → HTTP-запрос к `https://your-site.com/web/cron.php?key=CRON_SECRET_KEY`.

> `CRON_SECRET_KEY` генерируется при установке и сохраняется в `api/.env`.

### 4. Проверьте права ролей

Перейдите в админ-панель → **Роли** (`/index.php?route=admin-roles`). Проверьте, что у каждой роли корректные права. При необходимости скорректируйте.

### 5. Настройте почту (если пропустили)

В админ-панели → **Настройки** → **Почта** укажите SMTP-параметры и отправьте тестовое письмо.

## Устранение неполадок

### Ошибка «CRM уже установлен»

Удалите lock-файлы:

```bash
rm -f api/.install.lock storage_api/install.lock
rm -f api/.env
```

Или добавьте `?force=1` к URL установщика:
```
https://your-site.com/install/index.php?force=1
```

### Ошибка подключения к БД

Проверьте:
1. База данных **существует** на сервере MySQL
2. Пользователь имеет права `CREATE TABLE`, `INSERT`, `SELECT`, `UPDATE`, `DELETE`
3. Хост указан верно (обычно `localhost`, не `127.0.0.1` на shared-хостинге)
4. Порт `3306` не заблокирован файрволом

### «Нет прав на запись»

```bash
chmod -R 755 api/
chmod -R 777 storage_api/
```

На shared-хостинге — через файловый менеджер панели управления выставьте права `755` на `api/` и `777` на `storage_api/`.

### «Требуется PHP 8.1 или новее»

Обратитесь к хостинг-провайдеру для обновления версии PHP. На cPanel: **Select PHP Version** → выберите 8.1+.

### Отсутствует PHP-расширение

Список необходимых расширений: `pdo`, `pdo_mysql`, `mbstring`, `json`, `fileinfo`, `openssl`, `ctype`, `curl`.

На cPanel: **Select PHP Version** → отметьте нужные расширения. На VPS: `sudo apt install php8.1-mysql php8.1-mbstring php8.1-curl` (для Ubuntu/Debian).

### Письма не отправляются

1. Проверьте, что на шаге 8 тестовое письмо прошло успешно
2. Для SMTP: убедитесь, что порт `587` или `465` не заблокирован хостингом
3. Для Gmail: используйте [app-specific password](https://support.google.com/accounts/answer/185833)
4. Для mail(): некоторые shared-хостинги блокируют `mail()` — используйте SMTP

### После установки — белый экран

Проверьте:
1. Права на `api/.env` — должен читаться веб-сервером
2. Логи ошибок: `storage_api/logs/`
3. PHP error log на хостинге

## Переустановка

Для полной переустановки:

1. Удалите все таблицы CRM из базы данных
2. Удалите `api/.env` и `api/.install.lock`
3. Удалите `storage_api/install.lock` (если есть)
4. Откройте `install/index.php` заново

> ⚠️ Переустановка удалит все данные. Сделайте резервную копию перед переустановкой!

## Shared Hosting — Особенности

### Загрузка файлов

Архив CRM нужно распаковать в корневую директорию сайта. На разных панелях это:

- **cPanel**: `public_html/`
- **Plesk**: `httpdocs/`
- **ISPmanager**: `www/`
- **VestaCP**: `web/`

### Cron задачи

На shared-хостинге cron может быть недоступен. Альтернативы:
- [cron-job.org](https://cron-job.org) — бесплатный внешний cron-сервис
- [EasyCron](https://www.easycron.com) — альтернатива
- Встроенный планировщик хостинга (cPanel → Cron Jobs)

### Ограничения памяти

Если установщик падает с ошибкой памяти:
- Создайте `.htaccess` с `php_value memory_limit 256M`
- Или `ini_set('memory_limit', '256M')` (уже в коде)
- Обратитесь к хостинг-провайдеру

## Технические детали

### Что создаёт установщик

| Файл | Описание |
|------|---------|
| `api/.env` | Конфигурация: БД, ключи шифрования, настройки |
| `api/.install.lock` | Блокировка повторной установки |
| `storage_api/sessions/` | Файловые сессии |
| `storage_api/cache/` | Файловый кэш |
| `storage_api/logs/` | Логи ошибок |

### Ключи безопасности

При установке генерируются 5 криптографических ключей (по 256 бит каждый):

- `APP_KEY` — основной ключ шифрования
- `CSRF_SECRET_KEY` — защита от межсайтовых запросов
- `WEBHOOK_SECRET_KEY` — подпись вебхуков
- `AI_ENCRYPTION_KEY` — шифрование AI-ключей
- `CRON_SECRET_KEY` — защита cron-эндпоинта

Все ключи сохраняются в `api/.env` и **никогда не должны быть раскрыты**.
